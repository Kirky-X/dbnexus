## Project Overview

DB Nexus is an enterprise-grade database abstraction layer for Rust built on Sea-ORM. It provides:
- **Session Management**: RAII-style database connection lifecycle with automatic pool return
- **Permission Control**: Role-based table-level access control with YAML configuration
- **Connection Pooling**: Dynamic configuration with health checks and automatic tuning
- **Multi-Database Support**: SQLite, PostgreSQL, and MySQL with compile-time feature selection

## Database Feature Selection

The project requires exactly **one** database feature to be enabled at compile time:
- `sqlite` - SQLite via sqlx-sqlite
- `postgres` - PostgreSQL via sqlx-postgres
- `mysql` - MySQL via sqlx-mysql

These are mutually exclusive and will cause a compile error if multiple are enabled.

Optional features:
- `runtime-tokio-rustls` (default) - Tokio with RustLS
- `runtime-tokio-native-tls` - Tokio with native TLS
- `runtime-async-std` - Async-std runtime
- `metrics` - Prometheus metrics export
- `migration` - Database migration support
- `tracing` - Structured logging with tracing-subscriber
- `audit` - Audit logging
- `cache` - Caching layer
- `sharding` - Database sharding support
- `global-index` - Global index support
- `permission-engine` - Pluggable permission engine
- `auto-migrate` - Automatic migrations on pool creation

## Key Types

- `DbPool` - Manages database connections with min/max limits and idle timeout. Create with `DbPool::new(url)` or `DbPool::with_config(config)`.
- `Session` - RAII wrapper for database connection with transaction support and write tracking. Acquire via `pool.get_session(role)`.
- `DbResult<T>` - Type alias for `Result<T, DbError>`, the standard result type used throughout.
- `PoolStatus` - Connection pool status with `total`, `active`, and `idle` connection counts.
- `PermissionContext` - Role-based permission checking for table operations.
- `ActiveModel` - Generated by `#[derive(DbEntity)]` for CRUD operations.

## Macro System

### #[derive(DbEntity)]
Maps a Rust struct to a Sea-ORM Entity. Requires:
- `#[db_entity]` - Marker attribute
- `#[table_name = "table_name"]` - Database table name
- `#[primary_key]` - Mark the primary key field(s)

Generates `EntityTrait`, `ActiveModel` struct with `Set` fields, and `IntoActiveModel` implementation.

### #[db_crud]
Generates CRUD methods for entities:
- `insert(session, entity)` - Insert with auto-ID retrieval
- `find_by_id(session, id)` - Find by primary key
- `update(session, entity)` - Update record
- `delete(session, id)` - Delete by ID
- `find_all(session)` - Find all records
- `delete_many(session, filter)` - Batch delete
- `count(session)` - Count records

Each method calls `check_permission()` before execution. Uses default allow-all if not using `#[db_permission]`.

### #[db_permission]
Declare allowed roles and operations on a struct:
```rust
#[derive(DbEntity)]
#[db_entity]
#[table_name = "users")]
#[db_permission(role = "admin", actions = ["read", "write", "delete"])]
#[db_permission(role = "user", actions = ["read"])]
struct User {
    #[primary_key]
    id: i64,
    name: String,
}
```

Generates `ALLOWED_ROLES`, `ALLOWED_OPERATIONS` constants, `check_permission(ctx)` and `check_operation(ctx, operation)` methods.

### #[db_audit] and #[db_cache]
Optional macros for audit logging and caching support on entities.

### Important Restrictions
**Do NOT use `#[db_crud]` and `#[db_permission]` together on the same struct** - they will cause duplicate implementation errors. Use `#[db_crud]` alone for basic CRUD operations with default allow-all permissions, or implement custom permission checking manually.

### Example (basic CRUD without permissions)
```rust
use dbnexus::{DbPool, DbEntity, db_crud};

#[derive(DbEntity)]
#[db_entity]
#[table_name = "users")]
#[db_crud]
struct User {
    #[primary_key]
    id: i64,
    name: String,
}

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let pool = DbPool::new("sqlite::memory:").await?;
    let session = pool.get_session("admin").await?;

    let user = User {
        id: 0, // Auto-generated on insert
        name: "Alice".to_string(),
    };

    let inserted = User::insert(&session, user).await?;
    Ok(())
}
```

## Permission System

### YAML Configuration
Permissions can be configured via a YAML file referenced by `DB_PERMISSIONS_PATH`:
```yaml
roles:
  admin:
    tables:
      "*":
        actions: ["read", "write", "delete"]
  user:
    tables:
      users:
        actions: ["read"]
      orders:
        actions: ["read", "write"]
```

### Role Validation
When a permission config is loaded, `get_session(role)` validates that the role exists. Unknown roles fall back to deny-all policy.

### Built-in Permission Checks
- DDL operations (CREATE, DROP, ALTER) restricted to admin role
- System tables (sqlite_master, information_schema) bypass permission checks
- Complex/unparseable SQL in `execute_raw()` is rejected for security

## Data Flow

1. Create `DbPool::new(url)` or `DbPool::with_config(config)`
2. Acquire `Session` via `pool.get_session(role)` - role is validated against permission config
3. Perform database operations using Sea-ORM entities or raw SQL
4. Session automatically returns connection to pool on drop
5. Drop triggers automatic transaction rollback if uncommitted

## Testing with Docker

Integration tests require running databases. Start test containers:
```bash
# PostgreSQL
docker run --name dbnexus-test-postgres -e POSTGRES_PASSWORD=test \
  -e POSTGRES_DB=dbnexus_test -p 5432:5432 -d postgres:15

# MySQL
docker run --name dbnexus-test-mysql -e MYSQL_ROOT_PASSWORD=test \
  -e MYSQL_DATABASE=dbnexus_test -p 3306:3306 -d mysql:8

# Cleanup after testing
docker stop dbnexus-test-postgres dbnexus-test-mysql
docker rm dbnexus-test-postgres dbnexus-test-mysql
```

## Configuration Environment Variables

- `DATABASE_URL` - Connection string (required)
- `DB_MAX_CONNECTIONS` - Max pool size (default: 10)
- `DB_MIN_CONNECTIONS` - Min pool size (default: 1)
- `DB_IDLE_TIMEOUT` - Idle connection timeout in seconds (default: 300)
- `DB_ACQUIRE_TIMEOUT` - Connection acquire timeout in ms (default: 5000)
- `DB_PERMISSIONS_PATH` - Path to YAML permission configuration file
- `DB_AUTO_MIGRATE` - Enable automatic migrations (default: false, requires feature)
- `DB_MIGRATIONS_DIR` - Directory containing migration files (requires feature)
